# 《新世纪福音战士》角色档案内容审计

> 审计日期：2026-10-19  
> 审计范围：现有 `index.html`、`PRODUCT.md`、`DESIGN.md`、`assets/characters/CREDITS.md`、`assets/eva/CREDITS.md` 及角色图片旁的来源元数据。  
> 审计性质：只核对现有页面与资料，不修改实现文件；本报告不把“项目内存在”自动视为“作品设定已获权威出处证明”。

## 0. 结论摘要

1. 页面现有 9 个档案，数量与 `PRODUCT.md`、`DESIGN.md` 一致：主角团 5 个，反派主角团 4 个。
2. 主角团按当前集数排序没有明显逆序；反派阵营的 `A-01 碇源堂` 与 `A-02 萨基尔` 需要调整。两者都初登场于 EP.01，但萨基尔是这一集开场先出现的使徒，严格按画面初登场应排在碇源堂之前。若坚持源堂在前，应把规则改成“按叙事职能排序”，不能继续声称严格按初登场排序。
3. 用户提供的 18 条主体文案全部出现在页面中，逐字一致、无错字、无漏字，且每条第 1 次出现时均恰好分配一次。第 18 条“不必艳羡风月，孤岛有孤岛的好。”还作为终幕大标题再次出现，因此视觉上存在一次重复。
4. `SEELE` 档案的姓名字段不完整：页面没有独立日文名，并把 `SEVEN VOICES / HUMAN INSTRUMENTALITY` 放在本应是英文名的位置；这两段是描述语，不是组织名称。
5. `赤木律子` 的“MAGI 开发者”表述风险较高。MAGI 的系统原开发者通常归于赤木直子；律子更稳妥的身份表述是 MAGI 维护者、管理者或技术负责人。若保留“开发者”，必须补具体来源和贡献范围。
6. 页面把四种不同性质的内容放在相似的对白视觉位置：作品短引用候选、页面拟写指令、使徒信号字幕、合成朗读。所有音频都是 TTS，不是原声优录音；但现有“合成音声”只说明声音来源，没有说明台词文本是否官方原句。
7. `MAGI / 第三新东京市 / 2015` 雨夜视频与《新世纪福音战士》无关。`assets/eva/CREDITS.md` 明确记录其为拉斯帕尔马斯雨窗实拍，CC0 氛围素材；当前标题与字幕容易让观众误以为是官方 EVA 影像。
8. 角色立绘、群像、萨基尔插画及 SEELE 标志均不能视为已授权的官方宣传素材。页面页脚有非官方声明，但素材中间层仍缺少逐文件授权状态，公开传播前应重新清理权利链。

- **遗漏：0 条。** 18 条正文均已上页。

## 3. 事实、短引用、合成音声与设计文案

### 3.1 内容分类表

| 类型 | 页面中的内容 | 当前呈现 | 风险与建议 |
|---|---|---|---|
| 作品事实/档案事实 | 中英日姓名、适格者编号、机体、系统、身份、集数、日语集名 | 与作品设定混排 | 页面没有项目内出处脚注；迁移时应增加 `sourceRef`、适用连续性和核验状态 |
| 作品短引用候选 | 真嗣、美里、绫波丽、明日香、渚薰的角色台词 | 使用日语引号，像原作原句 | 需要补场景/集数/字幕版本；未核验前不要标成“官方原句” |
| 指令式拟态文案 | 律子“MAGI 系统，启动”、源堂“人类补完计划，开始”、SEELE 议会通讯 | 带日语引号、可播放 | 至少标注“页面拟态指令/非原句”；不能只标注“合成音声” |
| 使徒信号字幕 | 萨基尔“第三使徒、萨基尔。AT 力场，展开” | 与角色对白共享同一版式 | 明确写成无语音角色的“信号解码/字幕重现”，否则会被当成萨基尔真说过 |
| 用户设计文案 | 18 条独处文案、角色简介、双阵营命名、`SOLITUDE PROTOCOL`、同步率装饰 | 原创编辑内容 | 版权风险低，但会把“独处”主题投射到角色身上，不应写成角色官方独白 |
| 日语设计标语 | 首屏和终幕的「独りでいることは、自由であること。」 | 使用 `lang="ja"`，像作品宣传语 | 这是页面日文标语，不是已注明的官方标题；需要标“原创文案”或加英文说明 |
| 页面化数据 | `N-01`、`A-01`、`SYNC 41.2%`、`ACCESS DENIED`、`PATTERN / BLUE` | 使用 HUD、刻度和技术读数 | 这些是为版式创造的档案编号/演出数据，不是作品官方编号或计量结果 |
| 合成音声 | 9 条 MP3，由 edge-tts 生成 | 每张卡片均有“合成音声 · 非原声” | 标注方向正确；还应区分“朗读作品短引用”与“朗读页面拟写台词” |

### 3.2 容易误认为官方资料的表述

1. **整体官网感。** 大标题、官方日文标题、角色群像和 NERV/SEELE 标志会先建立“官方站点”预期；非官方声明只在页尾和素材说明中出现。建议首屏或固定导航持续显示 `FAN-MADE / 非官方同人`。
2. **`EVANGELION / SOLITUDE PROTOCOL`。** 英文副标题看起来像正式企划名，但没有来源；必须纳入原创设计文案。
3. **角色台词与拟写台词同版式。** 萨基尔、SEELE、律子和源堂的内容可能被读成官方对白。引用式视觉必须与作品原句、拟态字幕和设计文案分层。
4. **`SYNC 41.2%` 等数值。** 数值精确到小数会让人误以为来自官方设定；应标为装饰/演出数据。
5. **`THIRD ANGEL`、`HUMAN INSTRUMENTALITY` 被塞进英文名位置。** 这不是姓名数据，容易造成分类与姓名混淆。
6. **`SEVEN VOICES`。** 目前没有对 SEELE 成员数量、场景范围和版本口径的说明，不能作为无条件的官方事实。
7. **MAGI 式记录。** 雨夜视频版式标为 `MAGI / RECORD 00`、`第三新东京市`、`NERV CENTRAL DOGMA`、`MAGI ARCHIVE / 2015`，实际素材却是拉斯帕尔马斯雨窗实拍。应在画面内标注“氛围素材 / 非 EVA 原作影像”。
8. **“Official-style character art”表述。** `PRODUCT.md` 用这一说法描述 NeoApo 素材，容易被理解为官方风格或官方授权。应明确写“由第三方站点收录的角色图片，授权状态待核验”。
9. **SEELE 标志。** `DESIGN.md` 已说明这是唯一保留的官方标志类素材；它是真实商标/识别符号，不是页面自制几何图标，也不是已获授权证明。使用时应始终保留来源和非官方声明。
10. **事实来源缺位。** 集数、职务、机体和台词都在页面中陈述，但项目内没有逐条引用剧本、官方角色页或设定资料。内容迁移前应把“页面现有说法”与“已经核验的事实”分开。

## 4. 面向 `CharacterRecord` 的字段建议

以下只是字段设计建议，不包含实现代码。目标是同时容纳人物、使徒和组织，并把事实、短引用、合成音频、设计文案分开。

### 4.1 身份与连续性

| 字段建议 | 说明 |
|---|---|
| `id` | 稳定 ASCII 标识，例如 `shinji`；不能把显示名当主键 |
| `catalogCode` | 页面策展编号，例如 `N-01`；明确不是官方编号 |
| `faction` | 主角团/反派主角团的策展阵营；不要直接当作作品善恶判定 |
| `entityType` | 人物、使徒、组织三类至少分开；SEELE 不应与普通人物共用全部字段假设 |
| `continuity` | TV 1995、旧剧场版、新剧场版或复数；当前 9 条应先标为 TV 连续性 |
| `names.zh` | 中文常用名 |
| `names.ja` | 日文名；SEELE 应使用「ゼーレ」而不是留空 |
| `names.en` | 纯英文名，不拼接 `THIRD ANGEL` 或 `SEVEN VOICES` |
| `names.aliases` | 常见译名、称号、版本别名；明日香必须区分 Soryu/Shikinami |

### 4.2 登场与身份

| 字段建议 | 说明 |
|---|---|
| `firstAppearance.episodeNumber` | 例如 `1`、`2`、`8`、`24` |
| `firstAppearance.titleJa` | 日文集名，保留原文 |
| `firstAppearance.titleZh` | 中文标题或页面采用译文 |
| `firstAppearance.sceneOrder` | 同集内首次出现的镜头序号/场次；解决 EP.01 角色排序 |
| `firstAppearance.sourceRef` | 官方资料、设定集或剧本来源编号 |
| `identity.roles` | 适格者、司令、作战部长等身份 |
| `identity.affiliations` | NERV、SEELE 等归属；注意组织关系不等于单一角色 |
| `identity.machine` | EVA-00、EVA-01、EVA-02 等；非驾驶员可为空 |
| `identity.system` | MAGI 等系统；应把律子的职责和系统本身分成两个字段 |
| `identity.classification` | 第三使徒、第五适格者等分类；与英文名分开 |

### 4.3 编辑内容与媒体

| 字段建议 | 说明 |
|---|---|
| `shortBio` | 页面原创简介，显式标为编辑文案 |
| `solitudeLineIds` | 引用 18 条统一文案的稳定编号，例如 `L01`；不要复制成九份字符串 |

| `sourceRefs` | 作品事实、素材、职务、台词等所有来源引用 |

### 4.4 台词与音频

| 字段建议 | 说明 |
|---|---|
| `quote.ja` | 日语文本 |
| `quote.zh` | 中文译文 |
| `quote.kind` | `officialQuote`、`adaptedQuote`、`inWorldCommand`、`diegeticSignal`、`editorialCaption` 等概念分类 |
| `quote.isWorkExact` | 是否为经核验的作品原句；未知时不能默认 true |
| `quote.episodeNumber` / `quote.sceneRef` | 台词出处；像萨基尔这类无对白信号应写信号场景而非“说话”场景 |
| `quote.verificationStatus` | 未核验、已核验、有争议、页面拟写 |
| `audio.src` | 本地音频路径，例如 `assets/audio/ja/shinji.mp3` |
| `audio.language` | `ja` |
| `audio.text` | 与音频绑定的日文文本；避免播放路径与字幕再次错配 |
| `audio.synthesis` | 是否合成；当前 9 条均为 true |
| `audio.voiceProvider` / `audio.voiceId` | edge-tts 及模型记录，便于后续更换而不改展示内容 |
| `audio.isOriginalCast` | 当前全部为 false |
| `audio.disclosure` | “合成音声 · 非原声”；同时记录文本是否为拟写 |
| `audio.rightsStatus` | TTS 使用条件、声音模型许可、项目传播范围 |

### 4.5 页面状态与审计元数据

| 字段建议 | 说明 |
|---|---|
| `telemetry.label` / `telemetry.value` | 例如同步率；必须带“设计/演出数据”状态 |
| `theme` | 仅控制阵营视觉，不要混入角色事实 |
| `factStatus` | 事实核验状态 |
| `copyStatus` | 文案是否为用户原文、编辑文案或待改写 |
| `rightsStatus` | 素材和角色权利状态 |
| `lastReviewedAt` | 最近核对日期 |
| `notes` | 版本差异、翻译争议、无法证实内容 |

**迁移原则：**

- 一个对象只保留一种主名称，分类、称号和描述分别存放。
- 同集角色必须用 `sceneOrder` 解决排序，不能只依赖 `episodeNumber`。
- `quote` 和 `audio` 必须关联同一段 `text`，否则会出现新的错配。
- `solitudeLineIds` 应引用集中维护的 18 条文案表，避免出现一处改动、其他卡片未同步。
- 所有“看起来像官方事实”的字段都应有来源或明确标记为页面创作。
